# Sealed OpenWarrant inputs — prototype

Shared Warrant: `war://01a0f502-4941-70a1-a446-e1eb77dff191` ([OW-WAR-0149](https://github.com/Quitetall/OpenWarrant/tree/main/docs/warrants/OW-WAR-0149)). This is prototype implementation, not participant approval, contributor agreement or human assurance. Receipt schema, signature and hash domains stay v1.

`openwarrant verify --receipt RECEIPT --binding BINDING --sealed-inputs INPUTS` selects `blut/openwarrant-verification/v2`. Ordinary public-key/plan/job/producer options keep v1; mixing is refused. Both paths retain original signature, binding, plan/catalog, producer, native file and lifecycle checks. Neither runs a plan.

INPUTS is strict JSON, bounded to 8 MiB, with schema `blut/openwarrant-sealed-inputs/v1`, explicit `public_key`, `plan`, `producer_executable` descriptor paths, and complete `files` entries (`path`, original source `mode`, `descriptor`). Independent caller policy/capture supplies trust, coverage and source mode; never derive these from the receipt. Source mode is metadata. Each image remains non-executable. OpenWarrant must authenticate host policy, capture actual source modes and bind exact collector/Dispatch independently. This native interface authenticates none of those caller choices.

Only canonical `/proc/PARENT_PID/fd/FD` immediate-parent descriptors are accepted. Opened regular inputs must have no execute bits and must carry write/grow/shrink/execute/seal kernel locks. Unsupported platforms are unavailable; arbitrary links or mutable objects cannot substitute. The parent must hold all images until its child completes. Limits: key exactly 32 bytes, plan 2 MiB, producer 1 GiB, job file 64 MiB, aggregate job 256 MiB, 4,096 job files. Canonical paths, original modes and complete signed file table must agree. Original artifact references do not establish present availability or accepted delivery.

On Rust 1.99.0, all 12 native receipt tests passed; one helper is ignored by the default runner but explicitly invoked by the parent test. The CPU test validates after original-job removal and refuses mutable descriptors, changed bytes, changed source mode, duplicate paths and v1 substitution. All-target Clippy with warnings denied, fmt and whitespace checks passed. Actual native CLI accepted frozen inputs after moving the original job, refused mutable key and mixed transport options, and awarded no assurance. The fixture uses deliberately public key material and a synthetic transport-only binding, not actual OpenWarrant work authorization.

OpenWarrant's protected SDK/CLI connection, production custody, cost/confinement observations, participant acceptance and independent qualification remain. PR103 is a prerequisite with a failing CLA check; no agreement or merge is invented.
